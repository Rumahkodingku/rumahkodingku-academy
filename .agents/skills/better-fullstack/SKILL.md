# Better Fullstack Project

This project was generated by Better Fullstack. Treat the generated structure as
the source of truth when adding stack features, fixing bugs, or extending apps.

**This project was built with:** typescript ecosystem · next · nestjs backend (bun) · typeorm/mysql · tailwind. The authoritative record of these choices is `bts.jsonc`.

## Project Rules

- Use `pnpm` for package-manager commands.
- Do not start a dev server unless the user explicitly asks.
- Prefer package-local scripts over broad workspace commands.
- Keep generated stack choices in `bts.jsonc` in sync with scaffold changes.
- For new Better Fullstack options, prefer the local Better Fullstack CLI or MCP
  update flow instead of hand-authoring unrelated starter code.

## Common Commands

```bash
pnpm run check-types
pnpm run build
```

## Add a route or resource

This project runs a **nestjs** server in `apps/server/`. Add a new route by registering a handler on the app instance in `apps/server/src/` (see the existing route wiring) and export any shared logic from `packages/api` if present.

## Run migrations

This project uses the **typeorm** ORM (schema in `packages/db/src/`). Use the ORM's own migration CLI to generate and apply migrations after editing the entities/models.

## Add a test

Unit tests use **Vitest**. Add `*.test.ts` files next to the code under test and run:

```bash
pnpm run test
```

End-to-end tests use **Playwright** in `apps/web` - add specs under its `e2e`/`tests` directory and run the app's `test:e2e` script.

## Fallbacks

If a command is missing from the root package, inspect the relevant `apps/*` or
`packages/*` package before inventing a new workflow.
